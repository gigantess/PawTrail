# [요구사항 정의서] PawTrail 애자일 사용자 스토리 및 완료 정의 (DoD)

## 1. 개요 및 애자일 프레임워크 기준
* **프로젝트명**: PawTrail (반려견 맞춤형 안심 산책 에이전트 및 기록 플랫폼)
* **목표**: 5주간 스크럼(Scrum) 기반 2개 스프린트 및 안정화 기간을 통해 AI Agent 기반 무계단·완만 경사·그늘 우선 순환 라우팅, 현장 Vision 위험 분석, 개인화 Context Memory, Foreground GPS 산책 기록 및 외부 배포와 최소 5인 실사용자 필드 테스트를 완수.
* **스프린트 주기**:
  - **Sprint 1 (Week 1~2)**: 환경 구축, DB 스키마, Routing API Adapter, OSM Steps/경사도 분석, 후보 경로 스코어링 및 코어 Agent 파이프라인
  - **Sprint 2 (Week 3~4)**: 그늘 추정 모델, 현장 Vision 위험 판독 및 우회 재탐색, 모바일 UI 결합, Foreground 위치 기록, 열 위험 알림 및 외부 배포
  - **Hardening & Field Test (Week 5)**: 최소 5인 실사용자 필드 테스트, 피드백 기반 가중치/프롬프트 튜닝, 보안 및 최종 검증
* **추정 기준**:
  - **우선순위 (Priority)**: MoSCoW (Must / Should / Could / Won't)
  - **구현 난이도 (Complexity)**: 상 / 중 / 하
  - **추정 작업량 (Story Points)**: 피보나치 수열 (1, 2, 3, 5, 8 pt / 1 pt ≈ 순수 개발 0.5 MD)

## 3. 에픽별 상세 사용자 스토리 및 완료 정의 (DoD)

### [Epic A] 산책 조건 입력 및 개인화

#### US-A1: 대화형 자연어 산책 요청 및 조건 구조화
* **사용자 스토리**:  
  *반려견 견주로서*, 나는 "9살 노령견이라 계단은 피하고 완만한 길로 20분 정도 가볍게 산책하고 싶어"와 같이 자연어로 조건을 입력하고 싶다. *그리하여* 복잡한 지도 검색 없이 AI 에이전트가 내 요구를 정확히 이해해 최적의 코스를 구성해주기를 원한다.
* **우선순위**: Must | **난이도**: 중 | **Story Points**: 5 pt | **담당**: Member A (AI Agent)
* **인수 조건 (Acceptance Criteria)**:
  1. LangGraph Agent가 사용자 발화에서 `TargetDuration`, `AvoidStairs`, `SlopePreference`, `ShadePriority`, `SpecialConditions` 엔티티를 85% 이상의 정확도로 추출한다.
  2. 추출된 인자는 Pydantic V2 Strict Schema로 검증되며, 필수 정보 누락 시 친절한 확인 질문(Clarification)을 수행한다.
  3. UI 폼(슬라이더, 토글 버튼) 입력과 자연어 발화가 상호 동기화되어 동작한다.
* **완료 정의 (DoD)**:
  - [ ] 자연어 테스트 케이스 10종에 대한 엔티티 파싱 단위 테스트 통과.
  - [ ] REST API 엔드포인트(`POST /api/v1/walk/plan`) 연동 및 평균 파싱 지연 2초 이내 달성.

#### US-A2: 반려견 프로필(체급, 연령, 관절 상태) 등록 및 관리
* **사용자 스토리**:  
  *견주로서*, 나는 우리 아이의 견종, 체중, 연령, 관절 주의 상태를 한 번 등록해두고 싶다. *그리하여* 매번 산책 계획을 세울 때마다 신체 조건을 반복 입력하지 않기를 원한다.
* **우선순위**: Must | **난이도**: 하 | **Story Points**: 3 pt | **담당**: Member E, A (Infra/Agent)
* **인수 조건 (Acceptance Criteria)**:
  1. 온보딩 폼을 통해 견종, 체중, 연령, 관절 주의 수준(일반 / 완만길 선호 / 무계단 필수)을 등록/수정할 수 있다.
  2. 체급(소형/중형/대형) 및 관절 주의 여부에 따라 기본 보행 속도(2.4 ~ 4.2 km/h)가 자동 매핑된다.
  3. 의학적 질병 진단 용어를 강요하지 않고 견주가 이해하기 쉬운 웰니스 지표로 구성한다.
* **완료 정의 (DoD)**:
  - [ ] Supabase `dogs` 테이블 CRUD API 단위 테스트 및 RLS 권한 검증 완료.

#### US-A3: 목표 산책 시간/거리 기반 환산 및 프리셋 설정
* **사용자 스토리**:  
  *견주로서*, 나는 오늘 산책에 투자할 수 있는 시간(예: 15분, 30분, 45분)을 선택하고 싶다. *그리하여* 반려견의 체급별 보행 속도에 맞춰 제시간에 출발지로 되돌아오는 순환 코스를 얻기를 원한다.
* **우선순위**: Must | **난이도**: 중 | **Story Points**: 3 pt | **담당**: Member A, C (Agent/Backend)
* **인수 조건 (Acceptance Criteria)**:
  1. 원터치 칩(15분/30분/45분/60분) 및 5분 단위 슬라이더 지원.
  2. 반려견 속도를 반영한 목표 보행 거리 환산 ($\text{Target Distance} = \text{Speed} \times \text{Duration}$).
  3. 생성된 경로의 예상 소요 시간은 목표 시간의 $\pm 15\%$ 오차 범위 내로 수렴해야 한다.
* **완료 정의 (DoD)**:
  - [ ] 체급별 속도 기반 목표 거리 환산 모듈 단위 테스트 통과.

### [Epic B] 무계단·완만한 경사·그늘 우선 경로 생성

#### US-B1: 지도 데이터 기반 확인된 계단 구간 우선 회피
* **사용자 스토리**:  
  *관절이 약한 반려견의 견주로서*, 산책로 중간에 계단이 나오지 않기를 원한다. *그리하여* 관절에 무리를 주지 않고 편안하게 산책을 마치기를 원한다.
* **우선순위**: Must | **난이도**: 상 | **Story Points**: 8 pt | **담당**: Member C (Backend/GIS)
* **인수 조건 (Acceptance Criteria)**:
  1. OSM 보행 도로망 데이터에서 `highway=steps` 속성이 지정된 세그먼트를 감지하여 후보 경로 탐색 시 배제(Hard Constraint)한다.
  2. 단, 현장 지도 데이터의 결측 가능성을 인정하며 "100% 무계단 보장"을 주장하지 않고, 결과 객체에 `has_stairs: false`, `stairs_data_source: "osm"`, `stairs_confidence: 0.90` 메타데이터를 반환한다.
  3. 지형상 모든 우회로에 계단이 포함되어 무계단 경로가 불가능한 경우, 계단 수가 가장 적은 대안 코스를 제시하고 "일부 계단 구간 포함(사유 안내)"을 명시한다.
* **완료 정의 (DoD)**:
  - [ ] 계단 포함 구역과 우회 구역 테스트 케이스 5종에 대한 계단 회피 경로 생성 검증 통과.

#### US-B2: DEM 기반 최대 경사도 제어 및 완만한 경사 우선 경로 도출
* **사용자 스토리**:  
  *노령견 견주로서*, 숨이 차거나 다리에 부담이 되는 급경사 오르막/내리막을 피하고 싶다. *그리하여* 평지 위주의 완만한 산책로를 걷기를 원한다.
* **우선순위**: Must | **난이도**: 상 | **Story Points**: 5 pt | **담당**: Member C (Backend/GIS)
* **인수 조건 (Acceptance Criteria)**:
  1. DEM 고도 데이터 또는 라우팅 고도 프로파일을 연계하여 구간별 최대 경사도(`max_slope_percent`) 및 급경사 구간 비율(`steep_segment_ratio`)을 계산한다.
  2. UI에서는 "매우 완만 (3% 이하)", "완만 (6% 이하)", "제한 없음"으로 추상화하여 선택할 수 있다.
  3. 단순 평균 경사도만으로 판단하지 않고, 단일 구간이라도 급경사($> 8\%$)가 포함된 경우 페널티 비용을 부여하여 평지 우회로를 우선 탐색한다.
* **완료 정의 (DoD)**:
  - [ ] 구릉지 지형 샘플 좌표에 대해 급경사 링크 회피 및 완만 경로 도출 단위 테스트 통과.

#### US-B3: 태양 위치 및 건물 형상 기반 시간대별 그늘 우선 코스 평가
* **사용자 스토리**:  
  *견주로서*, 햇빛이 강한 낮 시간에 직사광선을 피해 그늘이 많은 길로 걷고 싶다. *그리하여* 반려견이 더위에 지치지 않도록 돕기를 원한다.
* **우선순위**: Should | **난이도**: 상 | **Story Points**: 5 pt | **담당**: Member C (Backend/GIS)
* **인수 조건 (Acceptance Criteria)**:
  1. 산책 예정 일시와 출발지 좌표를 기반으로 SunCalc를 통해 태양 고도각(Altitude) 및 방위각(Azimuth)을 계산한다.
  2. 가용 건물 2.5D/3D 외곽선 및 높이 데이터를 활용하여 보행 세그먼트의 예상 그림자 차폐 여부를 추정한다 (Level 1~2).
  3. 예상 그늘 비율(`shade_ratio`)을 산출하고, 직사광선 노출 구간보다 그늘 구간의 가중치를 우대하여 최적 경로를 평가한다.
  4. 그늘 정보는 확정 사실이 아닌 추정치이므로 `shade_estimation_source: "solar_building_model"`, `shade_confidence`를 함께 제공한다.
* **완료 정의 (DoD)**:
  - [ ] 정오(12시) vs 일몰 전(17시) 시간대별 태양 위치 변화에 따른 그늘 점수 산출 단위 테스트 통과.

#### US-B4: Routing API Adapter 연동 및 후보 경로 다요소 스코어링
* **사용자 스토리**:  
  *시스템으로서*, 전문 라우팅 API를 통해 수집된 여러 후보 경로 중 계단, 경사, 그늘 조건을 가장 잘 만족하는 최적의 순환 코스를 선별하고 싶다.
* **우선순위**: Must | **난이도**: 상 | **Story Points**: 8 pt | **담당**: Member C, A (Backend/Agent)
* **인수 조건 (Acceptance Criteria)**:
  1. OpenRouteService / OSRM 등의 전문 Routing API와 통신하는 독립 Adapter 레이어를 둔다.
  2. Agent가 생성한 Waypoint 조합을 바탕으로 2~3개의 후보 순환 경로(Candidate Routes)를 생성한다.
  3. Candidate Route Scoring 계층에서 계단 유무, 최대 경사, 그늘 비율, 목표 시간 수렴도를 종합 채점하여 1순위 추천 경로 및 대안 경로를 반환한다.
* **완료 정의 (DoD)**:
  - [ ] 모의 및 실제 라우팅 API 응답에 대한 Candidate Scorer 랭킹 알고리즘 단위 테스트 통과.

### [Epic C] 지도 표시 및 외부 내비게이션

#### US-C1: 구간별 안전/고도/그늘 속성 시각화 및 경로 프리뷰
* **사용자 스토리**:  
  *모바일 사용자로서*, 생성된 산책로의 구간별 상태(완만 구간, 그늘 구간, 주의 구간)를 지도 위에서 색상으로 한눈에 파악하고 싶다.
* **우선순위**: Must | **난이도**: 중 | **Story Points**: 5 pt | **담당**: Member D (Frontend)
* **인수 조건 (Acceptance Criteria)**:
  1. Next.js PWA 화면에서 반응형 지도 컴포넌트(MapLibre/Leaflet)를 통해 추천 루프 경로를 렌더링한다.
  2. 구간별 속성에 따라 Polyline 색상을 분기한다 (그늘/완만: 초록/청록, 일반: 파랑, 주의 경사: 주황).

### [Epic D] 현장 위험 분석 및 재탐색

#### US-D1: Vision AI 기반 현장 턱·계단·보행 장애물 시각 분석
* **사용자 스토리**:  
  *산책 중인 견주로서*, 앞길에 높은 턱이나 계단, 공사 구역이 보일 때 사진을 찍어 물어보고 싶다. *그리하여* 우리 아이 관절에 위험한지 판독받고 안전한 통행 가이드를 얻기를 원한다.

  2. 구조화된 JSON 스키마(`hazard_type`, `severity: low|medium|high`, `confidence`, `route_action: pass|caution|avoid_recommended`, `comment`)를 반환한다.
  3. 사진만으로 실제 지면 온도를 확정 측정한다고 표현하지 않으며, 시각적 장애 요인에 집중한다.
* **완료 정의 (DoD)**:
  - [ ] 현장 턱/계단/장애물 테스트 이미지 15종 대상 판독 단위 테스트 통과 (정확도 80% 이상).
  - [ ] REST API 엔드포인트(`POST /api/v1/surface/inspect`) 연동 완료.

#### US-D2: 현장 위험 구간 우회 및 동적 재탐색 (Reroute)
