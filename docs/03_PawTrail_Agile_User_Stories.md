# [요구사항 정의서] PawTrail 애자일 사용자 스토리 및 완료 정의 (DoD)

## 1. 개요 및 애자일 프레임워크 기준
* **프로젝트명**: PawTrail (반려견 맞춤형 안심 노면 산책 에이전트 및 기록·공유 플랫폼)
* **목표**: 5주간 스크럼(Scrum) 기반 2개 스프린트를 통해 AI Native 핵심 기능 개발, 클라우드 외부 배포, 최소 5인 실사용자 CBT 및 피드백 반영 완수.
* **스프린트 주기**:
  - **Sprint 1 (Week 1~2)**: 코어 AI 파이프라인(Agent, Vision, Memory) 및 라우팅 엔진 구축
  - **Sprint 2 (Week 3~4)**: UI/UX 결합, n8n 알림 자동화, 외부 배포 및 실사용자 5인 CBT
  - **Hardening & Launch (Week 5)**: 피드백 반영 고도화, 문서화 및 최종 데모
* **추정 기준**:
  - **우선순위 (Priority)**: MoSCoW (Must / Should / Could / Won't)
  - **구현 난이도 (Complexity)**: 상 / 중 / 하
  - **추정 작업량 (Story Points)**: 피보나치 수열 기반 (1, 2, 3, 5, 8, 13 pt / 기준: 1pt ≈ 개발자 0.5MD)

## 3. 세부 사용자 스토리 및 완료 정의 (Definition of Done)

### [Epic 1] 노면 맞춤형 AI 산책 플래닝

#### US-01: 대화형 산책 목표 및 조건 입력
* **사용자 스토리**:  
  *견주로서*, 나는 자연어 대화(예: "3살 말티즈, 관절 안심 케어 모드로 푹신한 길 위주 20분 코스 짜줘")를 통해 산책 시간과 반려견 상태를 전달하고 싶다. *그리하여* 복잡한 지도 검색 없이 즉시 맞춤형 산책 계획을 추천받기를 원한다.
* **우선순위**: Must | **난이도**: 중 | **Story Points**: 5 pt | **담당**: Member A (AI Agent)
* **인수 조건 (Acceptance Criteria)**:
  1. LangGraph Agent가 사용자 발화에서 `DogBreed`, `TargetDuration`, `Condition` 엔티티를 90% 이상의 정확도로 추출한다.
  2. 추출된 파라미터는 Pydantic V2 Strict Schema로 검증되며 필수 항목 누락 시 친절한 되물음(Clarification)을 수행한다.
* **완료 정의 (DoD)**:
  - [ ] 자연어 입력 테스트 케이스 10종에 대한 프롬프트 파싱 단위 테스트 통과.
  - [ ] REST API 엔드포인트(`POST /api/walks/plan`) 연동 완료 및 평균 파싱 지연 2초 이내.

#### US-02: 사용자 선호 노면 재질 선택 및 가중치 적용
* **사용자 스토리**:  
  *견주로서*, 나는 흙길, 잔디길, 우레탄/탄성포장, 보도블록 중 원하는 노면 재질을 직접 선택하고 싶다. *그리하여* 선택한 노면이 최우선으로 반영된 폭신한 산책로를 안내받기를 원한다.
* **우선순위**: Must | **난이도**: 중상 | **Story Points**: 5 pt | **담당**: Member A, C (Agent/GIS)
* **인수 조건 (Acceptance Criteria)**:
  1. UI(칩 선택) 또는 자연어로 1개 이상의 선호 노면 재질을 선택할 수 있다.
  2. 선택된 노면 링크에는 비용 할인 계수($W_{\text{pref}} = 0.4 \sim 0.5$)가 적용되고, 아스팔트는 2.5, 자갈은 3.5 페널티가 적용된다.
  3. 가용 보행 네트워크 내에서 선호 노면 비율을 최대한 확보하며, 도심지 등 주변 환경으로 인해 50% 미달 시 사용자에게 사유(예: "주변 잔디/흙길 부족으로 38% 구성")를 투명하게 안내하고, 필요 시 "탐색 반경을 1.5km로 넓혀볼까요?"와 같은 대안 재검색 옵션을 제공한다. (50% 무조건 강제 배제)
* **완료 정의 (DoD)**:
  - [ ] 선호 노면 선택 여부에 따른 링크 가중치 변환 단위 테스트 코드 작성.
  - [ ] 동일 출발점에서 '흙길 선택' vs '보도블록 선택' 시 서로 다른 경로가 생성됨을 맵 뷰어로 검증.

#### US-03: Waypoint 최적화 및 Routing API(ORS/OSRM) 연동 순환 라우팅 및 노면 추정(Fallback) 보정
* **사용자 스토리**:  
  *반려견과 함께 걷는 사용자로서*, 출발 지점(현위치/주차장)에서 시작하여 지정 거리를 걷고 다시 출발점으로 돌아오는 순환 경로를 원한다. *그리하여* 왔던 길을 되돌아가지 않고 안전하게 차량이나 집으로 복귀하기를 원한다.
* **우선순위**: Must | **난이도**: 중상 | **Story Points**: 8 pt | **담당**: Member C, A (Backend/Agent)
* **인수 조건 (Acceptance Criteria)**:
  1. "Waypoint 최적화 및 Routing API(ORS/OSRM) 연동 순환 라우팅" 방식을 채택하여, Agent가 Waypoint 후보를 선정한 뒤 표준 Routing API를 호출하고 노면 가중치 비용 평가를 거쳐 순환 루프 경로를 도출한다.
  2. 생성된 전체 경로 거리는 사용자의 목표 거리 대비 $\pm 15\%$ 이내 오차를 유지한다.
  3. **환경부 토지피복지도(Land Cover Map) 세분류 Spatial Join 적용**: 도로 링크와 환경부 토지피복 레이어 및 도시공원 폴리곤을 공간 결합하여 결측 링크의 노면 재질을 0.1초 만에 산정한다. 5인 CBT 시범구역은 사전 구축된 정사영상 육안 검증 시드(Seed) 데이터를 최우선 적용한다.
  4. 데이터 출처는 메타데이터(`surface_source: seed_verified | land_cover_map | park_polygon | community_verified | estimated`)로 투명하게 반환한다.
* **완료 정의 (DoD)**:
  - [ ] 10개 좌표 샘플에 대해 순환 경로 생성 연산이 2초 이내에 완료.
  - [ ] `LandCoverSpatialService` 공간 결합 단위 테스트 및 노면 출처 메타데이터 검증 완료.

#### US-16: 사용자 지정 산책 시간(Target Duration) 기반 맞춤형 코스 생성
* **사용자 스토리**:  
  *견주로서*, 내가 오늘 산책에 할애할 수 있는 시간(예: 15분, 30분, 45분, 60분 등)을 직접 입력하거나 선택하고 싶다. *그리하여* 반려견의 체급과 건강 상태에 따른 보행 속도를 반영해 해당 시간에 딱 맞춰 돌아오는 최적 순환 코스를 추천받기를 원한다.
* **우선순위**: Must | **난이도**: 중 | **Story Points**: 3 pt | **담당**: Member A, C (Agent/Backend) | **스프린트**: Sprint 1
* **인수 조건 (Acceptance Criteria)**:
  1. 플래너 UI에서 원터치 프리셋 칩(15분 / 30분 / 45분 / 60분) 및 5분 단위 슬라이더(최소 10분 ~ 최대 90분)를 제공하며, 자연어 발화("25분 정도 산책할래")로도 동일하게 설정 가능하다.
  2. 반려견 프로필의 체급 및 건강 상태(소형견 3.0km/h, 중형견 3.6km/h, 대형견 4.2km/h, 관절질환/노령견 2.4km/h)에 따른 평균 보행 속도를 적용하여 목표 보행 거리($\text{Target Distance} = \text{Walking Speed} \times \text{Target Duration}$)를 자동 환산한다.
  3. 생성된 순환 코스의 예상 소요 시간은 사용자가 지정한 목표 시간의 $\pm 10\%$ (또는 $\pm 3$분) 오차 범위 내로 수렴하는 후보 코스를 최소 2개 이상 생성한다. (※ v1에서는 평지 기준으로 산출하며, 경사도 및 횡단보도 대기 시간 보정은 Phase 2에서 반영)
* **완료 정의 (DoD)**:
  - [ ] 15분, 30분, 60분 입력 시 반려견 체급별 목표 거리 환산 로직 단위 테스트 통과.
  - [ ] 생성된 코스의 예상 소요 시간이 목표 시간의 오차 범위($\pm 10\%$) 내에 들어오는지 검증하는 라우터 알고리즘 테스트 통과.

### [Epic 2] 비전 멀티모달 현장 안전 진단

#### US-04: 비전 멀티모달 공원 종합안내판 판독 (`ParkBoardInspector`)
* **사용자 스토리**:  
  *견주로서*, 공원 입구에 도착했을 때 종합안내판 사진을 찍어 올리고 싶다. *그리하여* 공원 내 흙길/잔디마당의 정확한 위치와 반려견 출입 금지 구역(생태보존지역 등)을 사전에 시각적으로 파악하고 안전하게 코스에 반영하기를 원한다.
* **우선순위**: Must | **난이도**: 중 | **Story Points**: 5 pt | **담당**: Member B (Vision AI)
* **인수 조건 (Acceptance Criteria)**:
  1. 공원 입구 오프라인 종합안내판 사진 업로드 시 Gemini 1.5 Flash가 산책로 범례(흙길, 잔디밭, 포장로)와 반려견 출입 금지 구역을 3초 이내에 시각 분석한다.
  2. 구조화된 JSON 스키마(`ParkBoardInspectionResult`: `has_dirt_trail`, `has_grass_zone`, `dog_restricted_zones`, `detected_surfaces`, `confidence_score`, `summary_comment`)를 반환한다.
  3. 분석 결과는 즉시 플래너 에이전트의 구역 제약 조건으로 전달되어 출입 금지 구역을 자동 회피하고 흙길 진입로를 우선 경유하도록 경로 생성을 보정한다.
* **완료 정의 (DoD)**:
  - [ ] 공원 안내판 테스트 이미지 10종 대상 산책로/출입제한 식별 단위 테스트 통과.
  - [ ] REST API 엔드포인트(`POST /api/walks/inspect-board`) 연동 완료 및 평균 판독 지연 2.5초 이내.

#### US-05: 완주 후 커뮤니티 노면 제보 비전 검증 및 지도 속성 보정 (`CommunityMapEnricher`)
* **사용자 스토리**:  
  *견주로서*, 산책을 완주한 후 "이 구간 흙길이었음" 또는 "공사로 파쇄석 깔림"과 같은 사진 후기를 남기고 싶다. *그리하여* 비전 AI가 이를 자동 검증해 지도 데이터를 지속적으로 최신화하고 다른 견주들과 안전한 노면 정보를 나누기를 원한다.
* **우선순위**: Must | **난이도**: 중 | **Story Points**: 3 pt | **담당**: Member B, C (Vision/GIS)
* **인수 조건 (Acceptance Criteria)**:
  1. 완주 후 견주가 특정 링크에 사진 제보 등록 시, Gemini 1.5 Flash가 실제 노면 재질(`dirt`, `grass`, `rubber`, `paved`, `asphalt`, `gravel`)과 발바닥 부상 위험물(유리, 뾰족한 파쇄석 등)을 자동 검증한다.
  2. 구조화된 JSON 스키마(`SurfaceEnrichmentResult`: `verified_surface`, `is_safe_for_paws`, `hazard_detected`, `confidence`, `admin_approval_suggested`)를 반환한다.
  3. 판독 신뢰도 0.85 이상 시 해당 도로 링크의 노면 메타데이터(`surface_source: community_verified`)를 영구 갱신하고, 부상 위험물 검출 시 해당 링크에 회피 가중치(5.0)를 부여한다.
* **완료 정의 (DoD)**:
  - [ ] 커뮤니티 노면 제보 사진 20장 대상 비전 재질 분류 정확도 85% 이상 검증.
  - [ ] REST API 엔드포인트(`POST /api/walks/verify-surface`) 연동 및 DB 링크 속성 갱신 통합 테스트 통과.

### [Epic 3] 개인화 Long-term Memory

#### US-06: 반려견 건강 프로필 및 과거 산책 이력 기억 (Feedback Feedforward)
* **사용자 스토리**:  
  *견주로서*, 매번 반려견의 견종, 관절 안심 케어 선호도, 기본 선호 노면을 반복 입력하지 않고 싶다. *그리하여* 다음 로그인 시에도 이전 산책 피드백이 반영된 나에게 가장 최적화된 상태로 서비스를 이용하기를 원한다.
* **우선순위**: Must | **난이도**: 하 | **Story Points**: 3 pt | **담당**: Member E, A (Infra/Agent)
* **인수 조건 (Acceptance Criteria)**:

### 4.2 세부 사용자 스토리 및 인수 조건

#### US-17: 푹신한 길 영토 점령 (Green Hexagon) 시스템
* **사용자 스토리**:  
  *게이미피케이션을 즐기는 견주로서*, 일상적인 산책 중 내가 개척하고 걸은 '흙길·잔디길'이 동네 지도 위에 초록색 헥사곤(육각형 타일)으로 점령되는 시각적 보상을 얻고 싶다. *그리하여* 아스팔트 대신 더 많은 흙길을 찾아 산책하고, 동네 이웃 반려견들과 "우리 동네 흙길 마스터" 랭킹을 겨루며 산책 지속 동기를 얻기를 원한다.
* **벤치마킹 & PawTrail 차별화**:
  - *Pawland*: 25m 육각형 타일 점령 및 지역 영토 경쟁.
  - *PawTrail 차별화*: 일반 아스팔트 타일은 1배율 점수, 환경부 세분류 기반 흙길·잔디길 타일 점령 시 **2.5배 가중치(Green Bonus)**를 부여하여 관절 보호 산책을 자연스럽게 유도.
* **우선순위**: Should (Phase 2) | **Story Points**: 5 pt | **예상 리드타임**: 30 h
* **인수 조건 (Acceptance Criteria)**:
  1. H3 Hexagonal Hierarchical Spatial Index(해상도 10~11, 반지름 약 15~25m)를 사용하여 산책로 주변 공간을 타일화한다.
  2. 사용자가 GPS 산책 중 해당 헥사곤 내 노면이 '흙길/잔디길'일 경우 지도 타일이 형광 연두색('Green Turf')으로 점령 렌더링된다.
  3. 주간 동네 흙길 점령 랭킹보드(상위 10인) 및 '흙길 개척자' 뱃지 획득 기능을 제공한다.
* **완료 정의 (DoD)**:
  - [ ] Uber H3 알고리즘 기반 GPS 좌표-헥사곤 타일 ID 매핑 모듈 단위 테스트 통과.
  - [ ] Mapbox GL 벡터 레이어 상에서 100개 이상의 헥사곤 타일 60fps 부드러운 렌더링 검증.

#### US-18: 산책 중 한 손 원터치 배변 마킹 및 공원 편의시설(음수대/세족장) 핀 태깅
* **사용자 스토리**:  
  *리드줄을 잡고 있는 견주로서*, 산책 중 반려견이 대소변을 보거나 공원 내 반려견 음수대/세족장/배변봉투 수거함을 발견했을 때 한 손 조작만으로 지도에 즉시 핀을 남기고 싶다. *그리하여* 배변 기록(건강 모니터링)과 더불어 흙길 산책 후 발을 씻길 수 있는 세족장 위치 정보를 커뮤니티와 공유하기를 원한다.
* **벤치마킹 & PawTrail 차별화**:
  - *Petping / 산타*: 지도 위 소변/대변 1초 마킹 및 배변 횟수 기록.
  - *PawTrail 차별화*: 기존 다크포켓 모드(US-08)와 결합하여 화면을 보지 않고 음량 버튼 또는 한 손 스와이프로 즉시 배변 좌표 기록. 흙길 산책 특성상 필수적인 **'공원 세족장(Paw Wash Station)' 핀 공유 기능** 특화.
* **우선순위**: Must (Phase 2) | **Story Points**: 3 pt | **예상 리드타임**: 18 h
* **인수 조건 (Acceptance Criteria)**:
  1. 산책 중 화면 우측 하단 플로팅 버튼(FAB) 길게 누르기 또는 볼륨 하단 버튼을 통해 1초 만에 '대변/소변' 핀을 현재 GPS 위치에 마킹한다.
  2. 공원 내 시설물 핀 등록 모달에서 '반려견 세족장', '음수대', '배변봉투 수거함'을 선택해 커뮤니티 지도에 제보할 수 있다.
  3. 산책 종료 후 리포트에 오늘 산책 중 배변 횟수 및 위치가 타임라인 형태로 표시된다.
* **완료 정의 (DoD)**:
  - [ ] 배변 마킹 이벤트 GPS 로깅 및 DB 저장 REST API (`POST /api/walks/poop-event`) 계약 검증.
  - [ ] 세족장/음수대 커뮤니티 POI 등록 및 조회 단위 테스트 통과.

#### US-19: 관절 안심 걸음 누적 유기견 관절 영양제 기부 챌린지
* **사용자 스토리**:  
  *선한 영향력을 실천하고 싶은 견주로서*, 내 반려견과 함께 흙길·잔디길을 걸으며 절감한 관절 충격 에너지만큼 걸음 수를 포인트로 적립하고 싶다. *그리하여* 관절 질환을 앓고 있는 보호소 유기견들에게 관절 영양제나 사료를 기부하는 캠페인에 동참하여 높은 정서적 만족감을 얻기를 원한다.
* **벤치마킹 & PawTrail 차별화**:
  - *Piri Dogs (피리부는 고양이/강아지)*: 산책 350m당 발자국 획득 및 유기동물 보호소 사료 기부.
  - *PawTrail 차별화*: 단순 걸음 수가 아닌, **'노면 관절 안심 지표(흙길 비율 70% 이상)'를 달성한 보행 구간에 대해 기부 포인트 2배 적립(Joint Care Donation)**을 제공하여 펫 헬스케어 브랜드 스폰서십 모델과 연계.
* **우선순위**: Could (Phase 2) | **Story Points**: 3 pt | **예상 리드타임**: 18 h
* **인수 조건 (Acceptance Criteria)**:
  1. 산책 완주 리포트 생성 시 '관절 세이프 걸음 수(흙길/잔디길 보행 걸음)'를 자동 집계하여 기부 포인트로 전환한다.
  2. 기부 현황 대시보드에서 전국의 PawTrail 유저들이 함께 모은 누적 걸음 수와 기부 완료된 유기견 관절 영양제 수량을 실시간 프로그레스 바로 노출한다.
  3. 월간 기부 달성 시 유저 프로필에 '안심 기부 천사' 디지털 인증 배지를 발급한다.
* **완료 정의 (DoD)**:
  - [ ] 노면 완충 지표 기반 기부 포인트 계산 로직 단위 테스트 통과.
  - [ ] 기부 캠페인 프로그레스 바 UI 컴포넌트 렌더링 및 누적 통계 캐싱 검증.

#### US-20: 예민견·사회화 취약견을 위한 밀집도 역발상 회피 경로 (Reactive Dog Calm Trail)
* **사용자 스토리**:  
  *다른 반려견이나 낯선 사람을 보면 극도로 짖거나 흥분/불안해하는 예민견(Reactive Dog) 견주로서*, 다른 강아지들이 많이 몰리는 핫플레이스나 좁은 병목 골목을 피해, 마주침 확률이 현저히 낮고 시야가 넓게 트인 한적한 흙길 코스를 안내받고 싶다. *그리하여* 산책 중 돌발 충돌 사고나 스트레스 없이 반려견과 평화롭고 고요한 산책을 즐기기를 원한다.
* **배경 & 역발상 차별화 (Reverse Thinking)**:
  - *기존 펫 서비스의 한계*: 대부분의 펫 앱은 "강아지들이 많이 모이는 인기 산책로", "반려견 놀이터/소모임 스팟" 등 집결과 만남을 유도함.
  - *현실의 페인 포인트*: 공격성, 공포 트라우마, 발정기, 소형견-대형견 마주침 공포 등으로 인해 **"제발 다른 강아지와 마주치지 않고 조용히 걷고 싶다"**는 견주가 전체의 30% 이상 존재.
  - *PawTrail의 역발상 솔루션*: 인기 집결지를 '피해야 할 위험 비용(Encounter Penalty Cost)'으로 역전산하여, **한적한 시간대 + 시야 개방 폭 2m 이상의 외곽 오솔길 + 반려견 놀이터 반경 100m 회피 루프**를 설계.
* **우선순위**: Should (Phase 2) | **Story Points**: 5 pt | **예상 리드타임**: 26 h
* **인수 조건 (Acceptance Criteria)**:
  1. AI 플래닝 입력 시 "예민견 안심 산책 모드(Reactivity Solitary Mode)" 토글 옵션을 제공하며, 자연어 발화("강아지 마주치기 싫어", "다른 개 보면 짖어", "조용한 길로 가줘")에서 해당 의도를 90% 이상 파싱한다.
  2. 라우팅 비용 모델에 '밀집도 페널티(Density Penalty Factor)'를 적용하여, 공원 내 반려견 놀이터 인근 및 역사적 산책 피크 링크의 가중치를 3.0배 할증한다.
  3. 코너 시야가 꺾여 돌발 마주침 대처가 어려운 1m 미만 막다른 골목이나 좁은 통로를 제외하고, 회피 공간이 확보되는 2m 이상 개방형 흙길을 우선 선택한다.
* **완료 정의 (DoD)**:
  - [ ] 밀집 스팟 회피 가중치 적용 순환 경로 생성 알고리즘 단위 테스트 통과 (`test_reactive_dog_routing.py`).
  - [ ] REST API (`POST /api/walks/plan`) 요청 페이로드에 `avoid_dog_crowds: bool` 파라미터 연동 완료.

#### US-21: 사용자 온보딩 및 반려견 프로필 등록 플로우
* **사용자 스토리**:  
  *신규 사용자로서*, 앱 최초 실행 시 직관적인 온보딩 화면을 통해 반려견 이름, 사진, 견종, 체중, 나이, 관절 안심 케어 수준, 선호 노면을 한 번에 등록하고 싶다. *그리하여* 이후 모든 코스 생성에서 매번 입력을 반복하지 않고 즉시 맞춤 추천을 받기를 원한다.
* **배경 & 차별화**:
  - US-06(Memory)은 데이터 저장/조회를 다루지만, **최초 프로필 등록 온보딩 UX 플로우** 자체가 독립 스토리로 정의되어 있지 않음.
  - 실사용자 CBT(US-11) 시나리오 1번 "프로필 등록"이 첫 단계이나 이를 구현할 명확한 스토리가 부재.
* **우선순위**: Must (Phase 2 우선 투입 권장) | **Story Points**: 2 pt | **예상 리드타임**: 10 h
* **인수 조건 (Acceptance Criteria)**:
  1. 앱 최초 실행 시 3~4단계 스텝 기반 온보딩 위저드(견종 선택 → 체급/나이 → 관절 안심 케어 수준 → 선호 노면)를 제공한다.
  2. 온보딩 완료 시 반려견 프로필이 Firebase Cloud Firestore DB에 즉시 영속 저장되고, 이후 플래너 화면에서 자동 로드된다.
  3. 온보딩 건너뛰기 시 최소 필수 항목(견종, 체급)만 입력하도록 유도하는 축소 폼을 제공한다.
* **완료 정의 (DoD)**:
  - [ ] 온보딩 위저드 3~4단계 UI 렌더링 및 프로필 DB 적재 E2E 테스트 통과.
  - [ ] 온보딩 건너뛰기 시 최소 필수 항목 검증 로직 단위 테스트 통과.

#### US-22: 산책 중 긴급 산책 중단 및 귀환 경로 안내
* **사용자 스토리**:  
  *산책 중인 견주로서*, 갑작스러운 날씨 변화, 반려견의 컨디션 저하, 또는 개인 사정으로 산책을 즉시 중단하고 싶을 때 "지금 돌아가기" 버튼을 누르고 싶다. *그리하여* 현재 위치에서 출발점까지의 최단/최안전 귀환 경로를 즉시 음성으로 안내받기를 원한다.
* **배경 & 차별화**:
  - 핸즈프리 음성 안내(US-08)로 순환 코스를 걷다가 **중간 이탈/귀환이 필요한 실전 시나리오**가 빈번하나, 현재 어떤 US에도 "중도 귀환" 기능이 없음.
  - 반려견 산책 앱에서 매우 빈번한 사용 패턴이며, 특히 노령견/관절 안심 케어견 대상 필수 기능.
* **우선순위**: Should (Phase 2) | **Story Points**: 3 pt | **예상 리드타임**: 16 h
* **인수 조건 (Acceptance Criteria)**:
  1. 산책 진행 화면에서 "귀환" FAB 버튼 탭 또는 음성 명령("돌아갈래")으로 귀환 모드를 활성화한다.
  2. 현재 GPS 위치에서 출발점까지 최단 보행 경로를 2초 이내에 재산출하여 음성 안내를 즉시 전환한다.
  3. 귀환 경로도 가능한 범위 내에서 사용자 선호 노면을 우선 반영한다.
* **완료 정의 (DoD)**:
  - [ ] 귀환 경로 재산출 및 음성 안내 전환 E2E 테스트 통과.

#### US-23: 위치 정보 수집 동의 및 개인정보 처리 동의 플로우
* **사용자 스토리**:

* **배경 & 차별화**:

#### US-24: 다견 가구(Multi-Dog) 동시 산책 코스 최적화
* **사용자 스토리**:  
  *2마리 이상의 반려견을 키우는 견주로서*, 체급과 건강 상태가 다른 반려견들(예: 소형 노령견 + 대형 활동견)을 동시에 산책시킬 때 **모든 반려견에게 적합한 절충 코스**를 추천받고 싶다. *그리하여* 가장 약한 반려견 기준으로 안전하면서도 활동적인 반려견의 에너지도 소모할 수 있는 균형 잡힌 코스를 찾기를 원한다.
* **배경 & 차별화**:
  - 한국 다견 가구 비율 약 17%(2024 기준). 현재 US-06은 단일 반려견 프로필만 가정.
  - 다견 시 보행 속도 중 가장 느린 개체 기준 환산이 필요한 복합 로직이 미정의.
* **우선순위**: Should (Phase 2) | **Story Points**: 5 pt | **예상 리드타임**: 26 h
* **인수 조건 (Acceptance Criteria)**:
  1. 플래너 화면에서 2마리 이상의 반려견을 동시 선택할 수 있으며, 각 반려견의 프로필이 코스 생성에 반영된다.
  2. 보행 속도는 선택된 반려견 중 가장 느린 개체 기준으로 환산하고, 선호 노면은 모든 반려견의 선호를 합집합으로 적용한다.
  3. 코스 요약 카드에 "말티즈(관절 안심) + 골든 리트리버(활동형)" 등 동시 산책 반려견 정보가 표시된다.
* **완료 정의 (DoD)**:
  - [ ] 다견 선택 시 보행 속도 최솟값 환산 및 선호 노면 합집합 로직 단위 테스트 통과.
  - [ ] 다견 동시 산책 코스 생성 및 결과 카드 렌더링 E2E 검증.

#### US-25: 야간/저시야 산책 시 가로등 조도 기반 안전 경로 추천
* **사용자 스토리**:  
  *저녁 시간대에 산책하는 견주로서*, 어둡고 가로등이 없는 으슥한 길을 피하고 밝고 안전한 산책로를 우선 안내받고 싶다. *그리하여* 야간에도 반려견과 안심하고 산책하기를 원한다.
* **배경 & 차별화**:
  - 기획서의 "지면열 위험 시간대" 알림(US-12)은 낮 시간 위험만 다루며, 야간 산책 안전성(조도, 인적, CCTV 등)은 전혀 다루지 않음.
  - 퇴근 후 야간 산책이 전체 산책의 약 40%를 차지하는 현실 반영 필요.
* **우선순위**: Could (Phase 2) | **Story Points**: 5 pt | **예상 리드타임**: 26 h
* **인수 조건 (Acceptance Criteria)**:
  1. 일몰 이후 시간대에 코스 생성 시 "야간 안심 모드"를 자동 또는 수동으로 활성화할 수 있다.
  2. 공공데이터포털 가로등 위치 데이터 또는 OSM 조명 태그를 활용하여 조명이 확보된 보행로에 가중치 할인(0.6)을 적용한다.
  3. 조명 미확보 구간 진입 시 음성 안내로 "전방 어두운 구간입니다. 주의해주세요"를 사전 알림한다.
* **완료 정의 (DoD)**:
  - [ ] 야간 모드 조명 가중치 적용 라우팅 단위 테스트 통과.
  - [ ] 일몰 시각 자동 감지 및 야간 모드 전환 로직 검증.

#### US-26: 계절별/날씨 연동 실시간 노면 상태 경고 (비/눈 후 진흙탕 주의)
* **사용자 스토리**:  
  *비 온 다음 날 산책하는 견주로서*, 평소 좋아하는 흙길이 비/눈으로 인해 진흙탕이나 웅덩이가 되었을 가능성이 있을 때 **사전 경고를 받고 대안 포장길 코스를 추천**받고 싶다. *그리하여* 반려견이 진흙투성이가 되어 귀가 후 세척이 필요한 불편을 사전에 방지하기를 원한다.
* **배경 & 차별화**:
  - 현재 기획은 "좋은 날씨에 흙길을 걷는" 이상적 시나리오에 집중. 실제로 비 온 뒤 흙길은 진흙탕이 되어 오히려 기피 대상.
  - n8n 기상 자동화(US-12)와 연계하여 강수량 기반 노면 상태 동적 가중치 전환 가능.

* **인수 조건 (Acceptance Criteria)**:
  1. 최근 24시간 내 강수량이 10mm 이상인 경우, 흙길/비포장 노면의 기본 가중치를 2.0으로 상향하고 "진흙탕 주의" 경고를 코스 생성 결과에 표시한다.
  2. 사용자에게 "비 온 뒤 흙길 대신 탄성포장/보도블록 위주로 코스를 변경할까요?" 대안 옵션을 제공한다.
  3. n8n 워크플로우(US-12)의 기상 데이터를 재활용하여 강수량 기반 노면 상태 판정을 자동화한다.
* **완료 정의 (DoD)**:
  - [ ] 강수량 기반 흙길 가중치 동적 전환 로직 단위 테스트 통과.
  - [ ] 비 온 뒤 코스 생성 시 대안 경로 제안 UI 모달 렌더링 검증.
