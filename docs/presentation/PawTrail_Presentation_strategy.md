# 🎯 [발표 평가 가이드] PawTrail 핵심 페인 포인트 및 기술적 차별화 전략

> **발표 평가의 본질은 "기술의 단순 나열"이 아니라,  
> "진짜 사용자의 고통(Pain Point)을 정확히 짚어냈고, 현실적 데이터와 모바일 보행 환경의 제약 속에서 이를 어떻게 똑똑한 엔지니어링 의사결정(Engineering Decision)으로 풀어냈는가"를 증명하는 것입니다.**

본 문서는 PawTrail 최종 프로젝트 발표 시 심사위원과 평가관의 공감을 이끌어내고 최고 점수를 획득할 수 있도록 **[1] 사용자/도메인 페인 포인트**, **[2] 기존 상용 지도의 구조적 맹점**, **[3] 데이터 융합 및 5대 엔지니어링 돌파구**, **[4] 심사위원 예상 질문(Q&A) 방어 전략**, **[5] 슬라이드 스토리보드**를 체계적으로 정리한 발표 전용 전략 문서입니다.

## 1. 🎙️ 30초 오프닝 훅 (Elevator Pitch)

> *"국내 반려견의 대다수를 차지하는 소형견과 노령견에게 **'계단'**과 **'가파른 언덕'**은 관절에 치명적이고, 한낮의 **'직사광선'**은 체열 조절이 취약한 반려견을 지치게 만듭니다.  
> 특히 하네스 줄을 쥔 채 폰 화면을 들여다보며 걷는 것은 견주와 반려견 모두에게 매우 위험합니다.  
> **PawTrail은 반려견의 관절과 상태를 이해한 AI Agent가 계단과 급경사를 피하고 그늘을 우선하는 순환 산책로를 찾아주며, 폰은 주머니에 넣고 귀로 안내를 듣는 시선 해방(Eyes-Free) 핸즈프리 모바일 플랫폼입니다."*

## 3. 🗺️ 기존 상용 지도 서비스의 한계 (Market Blind Spots)

| 비교 항목 | 기존 상용 지도 (네이버 / 카카오 / 구글) | 반려견 안심 산책 플랫폼 (PawTrail) |
|---|---|---|
| **최적화 목적 함수** | **최단 거리 / 최단 시간** (도착 중심) | **계단 회피·완만 경사·그늘 우선** (과정 중심) |
| **경로 형태** | A 지점 $\to$ B 지점 편도 이동 | 출발지로 안전하게 되돌아오는 **순환형(Loop) 코스** |
| **보행 인터페이스** | ❌ 계속 화면을 보며 걸어야 함 (위험!) | ⭕ **주머니 속 백그라운드 핸즈프리 음성 안내 (안전!)** |
| **계단 식별** | ❌ 단순 도보 통행로로 통합 표시 | ⭕ OSM `highway=steps` 기반 **확인된 계단 우선 배제** |
| **경사도 분석** | ❌ 고도차 미제공 또는 단순 참고용 | ⭕ DEM 연계 **최대 경사도 및 급경사 구간 통제** |
| **그늘 환경 연산** | ❌ 지도상 그늘 정보 부재 | ⭕ **SunCalc 태양각 + 건물 형상 결합 그늘 구간 우선** |
| **현장 위험 대응** | ❌ 현장 장애물 우회 기능 부재 | ⭕ **Vision AI 사진 분석 기반 높은 턱/위험 안전 우회** |
| **프라이버시 관리** | ⚠️ 사용자 위치 서버 전면 수집 | ⭕ **자택 좌표 폰 로컬 보관 + 공유 시 200m 마스킹** |

## 4. 💡 엔지니어링 의사결정과 5대 기술적 돌파구 (Tech Pivots)

```mermaid
flowchart TD
    subgraph Problem ["초기 이상적 가설 (현실의 한계)"]
        P1["직접 A* GIS 엔진 코딩 시도<br/>(바퀴의 재발명 & 수치 오류)"]
        P2["계단 100% 무계단 보장 주장<br/>(OSM 결측치로 인한 과학적 결함)"]
        P3["Vision AI로 실시간 지면온도 측정<br/>(사진만으로 온도 측정 불가)"]
        P4["화면을 보며 걷는 모바일 웹<br/>(화면 꺼짐 시 GPS 끊김 & 보행 위험)"]
        P5["서버에 모든 위치/개인정보 축적<br/>(자택 위치 유출 및 개인정보 리스크)"]
    end

    subgraph Solution ["PawTrail 엔지니어링 돌파구 (현실적 혁신)"]
        S1["Routing API Adapter 제어<br/>(Agent가 조건 설정 & 전문 API 연산)"]
        S2["계단 회피 & 신뢰도 투명 명시<br/>(확인된 계단 배제 + 출처/신뢰도 표시)"]
        S3["Vision 시각위험 + 기상청 열지수 분리<br/>(턱/계단 판독 + 기상 데이터 열위험)"]
        S4["React Native Expo + 음성 길 안내<br/>(주머니 속 백그라운드 TTS + EAS 무선 OTA)"]
        S5["Privacy-First 로컬 보관 & 간편 이메일<br/>(폰에만 집 좌표 보관 + 200m 마스킹 공유)"]
    end

    P1 ==>|Pivot 1| S1
    P2 ==>|Pivot 2| S2
    P3 ==>|Pivot 3| S3
    P4 ==>|Pivot 4| S4
    P5 ==>|Pivot 5| S5
```

### [돌파구 1] 직접 A* 알고리즘 코딩 $\to$ Agent 도구 오케스트레이션 & Routing Adapter
* 전 세계 도로망을 직접 파싱하는 비효율을 걷어내고, 전문 **Routing API(ORS/OSRM) Adapter**에 도로망 연산을 위임. AI Agent는 다요소(계단/경사/그늘) 스코어링 및 최적 경로 선정에 집중.

### [돌파구 2] "100% 무계단 보장" 과장 $\to$ 확인된 계단 우선 회피 및 신뢰도 체계
* "100% 무계단 보장"이라는 비과학적 표현을 전면 배제하고, **"지도 데이터에서 확인된 계단 구간 우선 회피"**로 정의. 출처(`osm_tag`)와 신뢰도(`confidence: 0.92`)를 투명하게 표시.

### [돌파구 3] 사진으로 지면온도 측정 $\to$ 시각적 위험 분석과 열 위험 지수 분리
* 일반 사진 한 장으로 온도를 측정한다는 오류를 바로잡고, **Vision AI는 높은 턱, 야외 계단, 공사구간 판독**에 집중하며 **열 위험은 기상청 단기예보 모델**로 엄격히 분리.

### [돌파구 4] 화면을 보며 걷는 위험 $\to$ 주머니 속 백그라운드 핸즈프리 음성 안내 & EAS 무선 OTA
* **시선 해방(Eyes-Free) & 두 손 자유(Hands-Free)**:
  - 모바일 웹(PWA)은 화면을 끄면 백그라운드 GPS 및 음성이 끊겨 한 손에 리드줄을 쥐고 폰 화면을 봐야 하는 위험이 있었음.
  - **React Native (Expo SDK 51+) + Android Foreground Service**로 전환하여 스마트폰을 주머니에 넣고 화면을 꺼두어도 OSRM 스텝 기반 음성 브리핑(*"50m 앞 부드러운 완만길입니다. 우회전하세요"*)을 제공.
  - **EAS Build 1회 배포 + EAS Update 무선 OTA**로 스토어 심사나 APK 재설치 피로도 없이 즉시 핫픽스 배포.

### [돌파구 5] 서버 개인정보 무차별 수집 $\to$ Privacy-First 로컬 보관 & 간편 이메일 가입
* 사용자의 자택 주소, 보행 궤적, 반려견 신체 정보는 **사용자의 폰(`AsyncStorage`)에만 보관**.
* 소셜 로그인의 번거로움 없이 **간편 이메일 가입(Auto-confirm)**으로 진입장벽을 낮추고, 커뮤니티 코스 공유 시에만 **출발지/도착지 200m 자동 마스킹**을 적용해 사생활 완벽 보호.

## 5. 🤖 AI Native 산책 파이프라인의 완성 (How It Works)

```mermaid
sequenceDiagram
    autonumber
    actor User as 견주 (사용자)
    participant App as 📱 React Native 앱 (AsyncStorage)
    participant Navi as 백그라운드 음성 엔진 (expo-speech)
    participant Agent as LangGraph Agent (Stateless)
    participant Tools as Tool Layer (Routing/GIS/Vision)
    participant Cloud as ☁️ Supabase Cloud

    User->>App: 자연어 발화 ("관절 주의 노령견, 계단 피하고 완만한 20분 코스")
    App->>Agent: POST /api/v1/walk/plan (로컬 반려견 프로필 동봉)
    Agent->>Tools: Routing Adapter 경유지 샘플링 & 후보 수집
    Tools-->>Agent: 3개 순환 후보 경로 반환
    Agent->>Tools: Steps / Slope / Shade 다요소 스코어링
    Tools-->>Agent: 계단 0개, 최대경사 3.5%, 그늘 71% 최적 경로 선정
    Agent-->>App: 경로 GeoJSON + 음성 안내 스텝 반환
    User->>App: 산책 시작 후 폰을 주머니에 넣음 (화면 꺼짐)
    loop 백그라운드 보행 중 (Android Foreground Service)
        Navi-->>User: 폰 스피커/이어폰 음성 송출 ("50m 앞 완만길 우회전하세요")
    end
    opt 현장 턱 발견 시
        User->>App: 사진 촬영 업로드
        App->>Tools: Vision 위험 판독 (높은 턱 감지)
        Tools->>Agent: 우회 재탐색 트리거
        Navi-->>User: 음성 알림 ("전방 높은 턱 발견, 완만 우회로로 안내합니다")
    end
    User->>App: 산책 완주 (로컬에 궤적 및 체감 피드백 저장)
    opt 커뮤니티 공유 선택 시
        User->>App: "이 코스 공유하기" 클릭
        App->>Cloud: 출발지 200m 마스킹 블러링 후 코스 업로드
    end
```

## 6. 🛡️ 심사위원 킬러 질문(Q&A) 및 방어 전략 (Defense Matrix)

| 예상 질문 (Question) | 핵심 방어 논리 (Defense Script) |
|---|---|
| **Q1. 왜 모바일 웹이 아니라 React Native Expo 앱으로 피벗했나요?** | *"모바일 웹은 스마트폰 화면을 끄고 주머니에 넣으면 OS 정책상 GPS 추적과 음성 TTS가 멈춥니다. 당기는 힘이 강한 강아지 리드줄을 쥐고 한 손으로 화면을 보며 걷는 것은 보행 안전상 극도로 위험합니다. 저희는 **시선과 두 손을 해방시키는 진정한 핸즈프리 보행(Eyes-Free Navigation)을 완성하기 위해 React Native 백그라운드 포그라운드 서비스를 채택**했습니다."* |
| **Q2. 모바일 앱은 스토어 심사와 업데이트가 너무 느리지 않나요?** | *"그 점을 극복하기 위해 **EAS Build와 EAS Update (무선 OTA)** 파이프라인을 구축했습니다. 테스터에게는 APK를 단 1회만 배포하고, 이후 모든 기능 추가와 핫픽스는 웹 배포처럼 **무선 무점검 OTA로 실시간 업데이트**되므로 테스터의 재설치 피로도가 전혀 없습니다."* |
| **Q3. 개인정보를 폰에만 저장하면 폰을 바꿨을 때 다 날아가지 않나요?** | *"그래서 저희는 **'데이터 백업/복원(JSON 파일 내보내기/가져오기)'** 기능을 기본 탑재했습니다. 사용자가 원할 때 언제든 본인의 데이터를 파일로 다운받아 다른 기기로 안전하게 옮길 수 있어, 서버 유출 위험 없이도 데이터 연속성을 확보했습니다."* |
| **Q4. 커뮤니티에 코스를 공유하면 집 주소가 노출되지 않나요?** | *"그것을 방지하기 위해 **'출발지 200m 공간 마스킹(Spatial Jittering & Truncation)'** 파이프라인을 구축했습니다. 코스를 공유하더라도 사용자의 집 앞 골목길은 자동으로 잘려 나가고 큰길부터 공개되므로 안심하고 코스를 나눌 수 있습니다."* |
| **Q5. OSM 지도에 등록되지 않은 계단이 있으면 어떡하나요?** | *"그렇기 때문에 '100% 무계단 보장'이라는 과장을 배제하고 신뢰도를 투명하게 안내합니다. 또한 현장에서 예상치 못한 계단이나 높은 턱을 마주쳤을 때 **사진을 찍으면 Vision AI가 위험을 판독해 즉시 우회로를 찾아주는 상호보완적 안전망**을 제공합니다."* |
